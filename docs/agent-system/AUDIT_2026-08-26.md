# Audit — Casa Viva agent collaboration system

Date: 2026-08-26

## Scope

Audit the existing repository guidance and define a non-duplicative operating layer for supervising coding agents.

## Findings

### F-01 — `AGENTS.md` mixed durable rules with an outdated repo-wide stack assumption

The previous file correctly required inspection, small tasks, mobile-first work and Blueprint review, but it also said to maintain Next.js/App Router/TypeScript/Tailwind globally. That conflicts with the current canonical Messenger/operations implementation in WordPress/WooCommerce.

**Correction:** `AGENTS.md` is now a lightweight router. Stack rules are surface-specific.

### F-02 — Functional authority already existed and should not be duplicated

`CASA_VIVA_BLUEPRINT.md` already defines the order as the central unit, canonical roles/states, Messenger principles and the rule that nothing is done until the full flow is tested.

**Correction:** the new agent system links to the Blueprint instead of restating it.

### F-03 — Messenger already had a strong domain document

`MESSENGER_CENTER.md` already defines the canonical WordPress surface, current logistics, ownership, contact/route/payment boundaries and known degradations.

**Correction:** Messenger tasks must cite that document rather than creating another Messenger architecture document.

### F-04 — Missing layer was task translation and evidence semantics

The repository had architecture and testing documents, but no single contract that translated informal stakeholder language into Product/UX/UI/Copy/Engineering/QA requirements.

**Correction:** add `WORK_TASK_CONTRACT.md` and six focused skills.

### F-05 — “done” language was too ambiguous

Recent work demonstrated a false-positive closeout: CI/deploy success was described as pilot readiness although human mobile review still found UX/product defects.

**Correction:** add an evidence ladder and prohibit `PILOT_READY` from CI alone.

### F-06 — Lessons were not being converted into reusable rules

Repeated prompt growth addressed symptoms but did not create a durable learning mechanism.

**Correction:** add `LESSONS_LEDGER.md`; material failures must update a reusable rule.

## Non-duplication rule

The agent system contains **how to work**, not a second copy of **how Casa Viva works**.

Domain facts remain in the existing canonical documents. If a task discovers a domain fact is outdated, update the canonical domain document rather than the skill.

## Commercialization rule

Reusable method and lessons may be generalized into a service. Client-specific credentials, PII and commercial rules must never be included in reusable templates or case studies without authorization.

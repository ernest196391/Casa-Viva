# Service Playbook — Agent-Guided Product Improvement

## Purpose

Package the working method learned in Casa Viva into a reusable service for other businesses while keeping client-specific data, credentials and commercial rules isolated.

## Service promise

Turn an existing, partially built digital product into an ordered improvement program where:

- business language is translated into engineering contracts;
- coding agents implement bounded tasks;
- design/copy/UX rules are explicit rather than improvised;
- verification distinguishes code completion from product readiness;
- lessons from each failure improve the operating system.

## Engagement phases

### 1. Discovery audit

Collect the source of truth, repository map, current product surfaces, roles, critical flows and known pain points.

Output: current-state map and prioritized P0/P1/P2/P3 backlog.

### 2. Operating-system setup

Create or adapt:

- lightweight `AGENTS.md` router;
- domain source-of-truth documents;
- Product/UX/UI/Copy/Engineering/QA skills;
- task contract template;
- lessons ledger.

Output: repeatable collaboration contract for human + AI coding agent.

### 3. Focused remediation

Work one bounded task at a time:

`specify -> implement -> CI -> deploy -> human validate -> close`.

Output: small PRs with traceable acceptance criteria and rollback.

### 4. Release certification

Build a role/flow matrix and classify evidence as automated, production or human.

Output: explicit GO/NO-GO instead of subjective “looks done”.

### 5. Learning and handoff

Summarize:

- what was broken;
- root causes;
- corrections;
- reusable rules;
- measurable business benefits.

Output: client-facing case-study material and updated internal skills.

## What can be sold

Potential offers:

- AI-assisted product audit;
- coding-agent operating-system setup;
- UX/UI remediation supervision;
- agent prompt/task-contract design;
- release-readiness certification;
- ongoing AI engineering supervision;
- lessons-to-playbook documentation.

## Evidence to capture for case studies

For each material improvement record:

- before screenshot/problem;
- after screenshot/result;
- elapsed implementation cycles;
- number/type of defects prevented or removed;
- critical-flow completion rate;
- performance/resilience improvements when measurable;
- reduction in duplicated work or failed PR cycles;
- stakeholder/user validation.

Do not invent metrics retroactively. If a metric was not captured, describe the qualitative benefit and add instrumentation for future work.

## Privacy boundary

Never publish or reuse:

- credentials;
- private customer data;
- private order data;
- proprietary rates/commissions unless authorized;
- internal security details.

Generalize the reusable method, not the client's confidential business data.

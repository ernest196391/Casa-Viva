# Skill — Casa Viva Product

## Job

Translate an informal request into a product problem and a bounded outcome before engineering starts.

## Required questions

1. Who is the actor?
2. What are they trying to accomplish?
3. What is failing or creating friction now?
4. What must be true when the task is complete?
5. What must remain unchanged?
6. Is the issue P0, P1, P2 or P3?

## Priority

- `P0`: blocks the critical real-world flow, security, data integrity or money.
- `P1`: important capability materially broken or confusing.
- `P2`: UX/UI/copy defect that does not block the core flow.
- `P3`: enhancement or optimization.

## Rules

- Do not start from a requested UI treatment. First identify the outcome.
- Do not create a new engine when the repository already has an authority for that domain.
- Separate CURRENT fixes from FUTURE/Network work.
- One task contract should have one dominant product outcome.
- Define done in observable terms, not adjectives.

## Output

Produce the `WHY`, `TARGET BEHAVIOR`, `IN SCOPE`, `OUT OF SCOPE`, priority and business acceptance criteria sections of `WORK_TASK_CONTRACT.md`.
